## Лабораторная 4 — вёрстка

### Box model карточки (часть 1)

- content: около 200px, padding: 16px, border: 1px, margin: 0
- с box-sizing: border-box итоговая ширина карточки становится предсказуемой и не выходит за заданный контейнер

### repeat(4, 1fr) на узком экране (часть 4)

При сужении окна до ~500px сетка начинает уменьшать количество колонок и карточки встают в несколько рядов, что демонстрирует адаптивность Grid без отдельной media query.

### auto-fit vs auto-fill (часть 4)

auto-fit подгоняет колонки под доступное пространство и убирает пустые слоты, а auto-fill сохраняет фиксированную сетку и оставляет пустые колонки при небольшом числе товаров.

## Тестирование

- `npm test` запускает 15 Vitest-тестов: ProductCard (3), LoginForm (4), состояния каталога в App (5), apiFetch (2) и smoke-проверку (1).
- `npm run coverage` создаёт HTML-отчёт в `coverage/`. Последний сохранённый отчёт показывает **61% Lines**; обновите значение после нового запуска перед сдачей. Наименее покрыт `AddProductForm.jsx` (0% Lines): его отправка, обработка ошибки и успешное добавление пока не проверяются компонентными тестами.
- `npm run e2e` запускает desktop browser-сценарии локально. Нужны запущенный Vite и backend с доступной PostgreSQL.
- `npm run e2e:prod` проверяет опубликованный сайт, API и базу; локальная PostgreSQL не нужна. Тест регистрации создаёт пользователя, а форма заявки — заказ в production, поэтому используйте уникальный тестовый email и учитывайте, что данные останутся в базе.
- В Windows CMD перед `npm run e2e:prod` задайте `set "E2E_BASE_URL=https://full-stack-1-smoky.vercel.app"`. `npx playwright show-report` открывает HTML-отчёт после запуска тестов.
- Playwright также проверяет навигацию и ширину карточки на Pixel 7. В GitHub Actions production E2E запускается вручную или ежедневно; unit-тесты и сборка запускаются в PR CI.
