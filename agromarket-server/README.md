# АгроМаркет API

REST API на Express с PostgreSQL для каталога товаров и оптовых заявок.

## Запуск

1. Установите Node.js и PostgreSQL.
2. Создайте базу `agromarket` через pgAdmin или командой `CREATE DATABASE agromarket;`.
3. Скопируйте `.env.example` в `.env` и укажите пароль пользователя PostgreSQL в `DATABASE_URL`.
4. Установите зависимости и создайте таблицы, загрузив начальные товары:

   ```sh
   npm install
   npm run db:init
   ```

5. Запустите сервер:

   ```sh
   npm run dev
   ```

По умолчанию API доступен на `http://localhost:3000`. Настройки `DATABASE_URL`, `PORT` и `CORS_ORIGIN` задаются в `.env`. Не добавляйте `.env` в Git; `.env.example` содержит только шаблон.

`npm run db:init` создаёт отсутствующие таблицы и загружает товары из `data/db.json`, только если таблица товаров пуста. Повторный запуск сохраняет имеющиеся данные. В исходном JSON есть одна демонстрационная запись с некорректными `name` и `price`; скрипт сообщает о ней и пропускает её.

## Эндпоинты

| Метод | Путь | Описание | Ответы |
| --- | --- | --- | --- |
| GET | `/api/health` | Состояние API и подключение к БД | 200, 500 |
| GET | `/api/products` | Список товаров; фильтр `?search=мол` | 200 |
| GET | `/api/products/:id` | Получить товар | 200, 400, 404 |
| POST | `/api/products` | Создать товар | 201, 400 |
| PUT | `/api/products/:id` | Полностью заменить товар | 200, 400, 404 |
| DELETE | `/api/products/:id` | Удалить товар | 204, 400, 404 |
| GET | `/api/orders` | Заявки с названиями товаров | 200 |
| POST | `/api/orders` | Создать заявку | 201, 400 |
| PATCH | `/api/orders/:id` | Изменить статус заявки | 200, 400, 404 |

Для создания и изменения товара обязательны `name` и целочисленный `price` не меньше нуля. В заявке обязательны `name`, `email` и `quantity` (не менее 10); `product_id`, `phone`, `date`/`deliveryDate` и `comment` необязательны. Для совместимости с текущей React-формой сервер также принимает `volume`.

Допустимые статусы заявки: `new`, `processing`, `done`, `cancelled`. Значения клиента передаются в SQL параметрами (`$1`, `$2` и т. д.). Ограничения PostgreSQL преобразуются в ответы `400`; неожиданные ошибки записываются в журнал сервера, клиент получает общее сообщение `500`.

## Postman

Импортируйте [`postman/agromarket.postman_collection.json`](./postman/agromarket.postman_collection.json) в Postman. Коллекция проверяет доступность БД, чтение и CRUD товаров, создание заявки, валидацию и смену статуса. Запускайте её, когда сервер и база данных доступны.

## Тесты

```sh
npm test
```

Unit-тесты проверяют маршруты, валидацию и совместимость полей формы React. End-to-end-проверки API и базы находятся в Postman-коллекции.

## Ответы и пояснения к лабораторной

- Первичные ключи `products.id` и `orders.id` уникально идентифицируют строки. `orders.product_id` — внешний ключ на товар; `ON DELETE SET NULL` сохраняет заявку, если её товар удалён.
- `NOT NULL` запрещает пропуск обязательных полей, `CHECK` ограничивает цену, объём и статусы, внешний ключ не позволяет привязать заявку к несуществующему товару.
- CRUD соответствует SQL `SELECT`/`INSERT`/`UPDATE`/`DELETE` и HTTP `GET`/`POST`/`PUT`/`DELETE`. Создание отвечает `201`, успешное удаление — `204` без тела. `PUT` заменяет товар целиком, а `PATCH` меняет только статус заявки.
- SQL-инъекция предотвращается параметризованными запросами: ввод клиента передаётся как значение, а не конкатенируется с текстом SQL.
- Объём заказа проверяется и в Express, и ограничением `CHECK (quantity >= 10)` в БД: API даёт понятную ошибку до запроса, а БД остаётся последней защитой для всех клиентов.
- Ошибки PostgreSQL `22P02`, `23502`, `23503` и `23514` централизованно преобразуются в ответы `400`; детали неожиданных ошибок остаются в серверном журнале.
