# АгроМаркет API

![CI](https://github.com/timonk201/full_stack_1/actions/workflows/ci.yml/badge.svg)

REST API на Express с PostgreSQL для каталога товаров и оптовых заявок.

Репозиторий содержит backend в `agromarket-server/` и frontend в `agromarket-react/`. Команды backend выполняйте из `agromarket-server`, команды frontend — из `agromarket-react`.

## Запуск

1. Установите Node.js и PostgreSQL.
2. Создайте базу `agromarket` через pgAdmin или командой `CREATE DATABASE agromarket;`.
3. Скопируйте `.env.example` в `.env` и укажите пароль пользователя PostgreSQL в `DATABASE_URL`.
4. Установите зависимости и создайте таблицы, загрузив начальные товары:

   ```sh
   npm install
   npm run db:init
   ```

5. Запустите сервер:

   ```sh
   npm run dev
   ```

По умолчанию API доступен на `http://localhost:3000`. Настройки `DATABASE_URL`, `PORT`, `CORS_ORIGIN`, `JWT_SECRET`, `JWT_EXPIRES_IN`, `ADMIN_EMAIL` и `ADMIN_PASSWORD` задаются в `.env`. Не добавляйте `.env` в Git; `.env.example` содержит только шаблон.

`npm run db:init` пересоздаёт таблицы, загружает товары из `data/db.json` и создаёт администратора из `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Учтите, что повторный запуск удалит текущие товары и заявки. В исходном JSON есть одна демонстрационная запись с некорректными `name` и `price`; скрипт сообщает о ней и пропускает её.

## Переменные окружения

Сгенерируйте `JWT_SECRET` случайным ключом длиной 32 байта (64 шестнадцатеричных символа):

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Укажите ключ в `.env`, например вместе с `JWT_EXPIRES_IN=2h`, `ADMIN_EMAIL=admin@agromarket.kz` и `ADMIN_PASSWORD=<свой пароль>`. Шаблон `.env.example` содержит только безопасные значения-заглушки. Не публикуйте `.env` и не помещайте реальные секреты в клиентский код.

## Эндпоинты

| Метод | Путь | Доступ | Описание | Ответы |
| --- | --- | --- | --- | --- |
| GET | `/api/health` | Все | Состояние API и подключение к БД | 200, 500 |
| POST | `/api/auth/register` | Все | Регистрация пользователя | 201, 400, 409 |
| POST | `/api/auth/login` | Все | Вход и получение JWT; максимум 5 неудачных попыток за 15 минут с IP | 200, 400, 401, 429 |
| GET | `/api/auth/me` | Bearer JWT | Данные текущего пользователя | 200, 401, 404 |
| GET | `/api/products` | Все | Список товаров; фильтр `?search=мол` | 200 |
| GET | `/api/products/:id` | Все | Получить товар | 200, 400, 404 |
| POST | `/api/products` | admin | Создать товар | 201, 400, 401, 403 |
| PUT | `/api/products/:id` | admin | Полностью заменить товар | 200, 400, 401, 403, 404 |
| DELETE | `/api/products/:id` | admin | Удалить товар | 204, 400, 401, 403, 404 |
| GET | `/api/orders` | admin | Заявки с названиями товаров | 200, 401, 403 |
| POST | `/api/orders` | Все | Создать заявку | 201, 400 |
| PATCH | `/api/orders/:id` | admin | Изменить статус заявки | 200, 400, 401, 403, 404 |

Тела JSON-запросов ограничены 10 КБ; слишком большое тело получает `413`, некорректный JSON — `400`. Сервер добавляет защитные HTTP-заголовки Helmet и не запускается без `JWT_SECRET`.

Для создания и изменения товара обязательны `name` и целочисленный `price` не меньше нуля. В заявке обязательны `name`, `email` и `quantity` (не менее 10); `product_id`, `phone`, `date`/`deliveryDate` и `comment` необязательны. Для совместимости с текущей React-формой сервер также принимает `volume`.

Допустимые статусы заявки: `new`, `processing`, `done`, `cancelled`. Значения клиента передаются в SQL параметрами (`$1`, `$2` и т. д.). Ограничения PostgreSQL преобразуются в ответы `400`, повтор уникальной записи — в `409`; неожиданные ошибки записываются в журнал сервера, клиент получает общее сообщение `500`.

## Postman

Импортируйте [`postman/agromarket.postman_collection.json`](./postman/agromarket.postman_collection.json) в Postman. Перед запуском укажите пароль администратора в переменной коллекции `adminPassword`; коллекция сама получает admin JWT, регистрирует обычного пользователя и проверяет ответы 401/403 перед CRUD-сценариями.

## Тесты

Создайте отдельную базу `agromarket_test`, затем скопируйте `.env.example` в `.env.test`, укажите тестовую базу и пароль PostgreSQL. Файл `.env.test` игнорируется Git.

Установите инструменты тестирования:

```sh
npm install -D vitest supertest @vitest/coverage-v8
```

```sh
npm test
npm run test:watch
npm run coverage
```

`npm test` запускает интеграционные и модульные тесты, а затем существующие проверки на `node:test`. Отчёт покрытия создаётся в `coverage/`. В текущем запуске `npm run coverage` покрытие Lines составило **59,5% (97 из 163 строк)**.

## Ответы и пояснения к лабораторной

- У пользователей с одинаковым паролем bcrypt-хэши разные: к каждому хэшированию добавляется случайная соль.
- Регистрация с переданным `"role": "admin"` всё равно создаёт пользователя с ролью `user`: сервер не принимает роль из тела запроса.
- Изменённый JWT не проходит проверку, потому что подпись вычислена по исходным данным и `JWT_SECRET`; изменение роли меняет payload и делает подпись недействительной.
- При испорченном или истёкшем токене защищённый запрос получает `401`; `apiFetch` удаляет `token` и `user` из `localStorage` и перезагружает страницу.
- Скрытие формы товара в React не защищает API: запрос можно отправить вручную. Настоящая проверка выполняется на сервере через `requireAuth` и `requireRole('admin')`.
- Да, при выполнении лабораторной использовался GitHub Copilot для реализации и проверки кода, тестов и документации.
- Запрос `OPTIONS` — это CORS preflight: браузер заранее проверяет, разрешены ли запрос с текущего origin и заголовок `Authorization`; middleware `cors` отвечает до передачи запроса маршруту.
- Первичные ключи `products.id` и `orders.id` уникально идентифицируют строки. `orders.product_id` — внешний ключ на товар; `ON DELETE SET NULL` сохраняет заявку, если её товар удалён.
- `NOT NULL` запрещает пропуск обязательных полей, `CHECK` ограничивает цену, объём и статусы, внешний ключ не позволяет привязать заявку к несуществующему товару.
- CRUD соответствует SQL `SELECT`/`INSERT`/`UPDATE`/`DELETE` и HTTP `GET`/`POST`/`PUT`/`DELETE`. Создание отвечает `201`, успешное удаление — `204` без тела. `PUT` заменяет товар целиком, а `PATCH` меняет только статус заявки.
- SQL-инъекция предотвращается параметризованными запросами: ввод клиента передаётся как значение, а не конкатенируется с текстом SQL.
- Объём заказа проверяется и в Express, и ограничением `CHECK (quantity >= 10)` в БД: API даёт понятную ошибку до запроса, а БД остаётся последней защитой для всех клиентов.
- Ошибки PostgreSQL `22P02`, `23502`, `23503` и `23514` централизованно преобразуются в ответы `400`; детали неожиданных ошибок остаются в серверном журнале.

## Продакшен

После создания сервисов замените адреса-заглушки ниже на фактические URL:

- Сайт: `https://<имя-проекта>.vercel.app`
- API: `https://<имя-сервиса>.onrender.com/api/health`
- Схема: React (Vercel) → Express (Render) → PostgreSQL (Neon)

Для монорепозитория укажите `agromarket-server` как Root Directory Render-сервиса, а `agromarket-react` — как Root Directory Vercel-проекта.

### Переменные окружения

| Переменная | Где задаётся | Секрет |
|---|---|---|
| `DATABASE_URL` | Render | Да |
| `JWT_SECRET` | Render | Да |
| `CORS_ORIGIN` | Render | Нет |
| `VITE_API_URL` | Vercel | Нет |
| `RENDER_DEPLOY_HOOK_URL` | GitHub Actions Secrets | Да |
| `API_URL` | GitHub Actions Variables | Нет |
| `FRONTEND_URL` | GitHub Actions Variables | Нет |

Render: Build Command — `npm ci --omit=dev`; Start Command — `npm run db:migrate && npm start`; Health Check Path — `/api/health`. Отключите Auto-Deploy, чтобы деплоем управлял GitHub Actions.

### Конвейер деплоя

1. Pull Request запускает backend-тесты и frontend lint/build.
2. Push в `main` после успешных проверок запускает Render Deploy Hook для проверенного SHA.
3. Smoke-тест ждёт появления этого SHA в `/api/health`, затем проверяет БД, каталог, запрет создания товара без токена, CORS и ответ `404`.
4. Vercel собирает frontend из `main`; при аварии выполните rollback на Render и оформите исправление через `git revert` в Pull Request.

После создания облачных сервисов добавьте в GitHub Secret `RENDER_DEPLOY_HOOK_URL` и Variables `API_URL` (URL API вместе с `/api`) и `FRONTEND_URL` (origin сайта без завершающего слэша). Задайте на Render `CORS_ORIGIN` списком разрешённых origin через запятую.
